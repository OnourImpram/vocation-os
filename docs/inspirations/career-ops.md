# Career Ops Inspiration and Clean-Room Boundary

VocationOS 0.7 was informed by the public design vocabulary of the `santifer/career-ops` project, particularly its filter-first philosophy and its insistence that career automation should not optimise raw application volume.

The following workflow ideas influenced the VocationOS product design:

- liveness checking before spending effort on a vacancy,
- separate posting-legitimacy analysis,
- holistic role evaluation rather than keyword matching alone,
- deep company research for the strongest opportunities,
- one-target contact strategy,
- bounded follow-up cadence,
- repost detection,
- reply classification,
- funnel and source-performance analysis.

VocationOS does not copy Career Ops source code. The implementation is clean-room and is expressed through VocationOS-native contracts:

- claim and evidence graphs,
- immutable source observations,
- three-stage verification bundles,
- deterministic legitimacy signals,
- signed execution grants,
- transactional idempotent Outbox commands,
- compiled adapter authority,
- application lifecycle state machines,
- trusted collector receipts,
- encrypted local event history,
- separated agent capabilities.

Career Ops and VocationOS therefore address related but distinct layers. Career Ops demonstrates a rigorous candidate workflow. VocationOS makes consequential career actions evidence-bound, authorised, replay-resistant, auditable, and impossible to record as complete without trusted proof.

The public VocationOS repository includes only synthetic fixtures. It contains no Career Ops code, private candidate data, recruiter addresses, platform credentials, or live browser sessions.
